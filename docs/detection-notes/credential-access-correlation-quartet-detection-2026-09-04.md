# Six Credential-Access Correlation Rules: LSASS Dumping, Failed-Logon Bursts, and Printer-Credential Harvesting

Six correlation-rule-pair detections across six named actors, covering three distinct credential-access mechanisms — unlike this session's T1567/T1486 clusters, this set is NOT uniformly identical; four of the six share one signature (failed-logon bursts) while the other two are each genuinely distinct.

## What each rule actually detects

**1. DragonForce — LSASS memory-access burst (T1003, `process_creation`).** Base match: a process opening `lsass.exe` with one of three specific `GrantedAccess` masks (`0x1010`, `0x1410`, `0x1438`) — access rights consistent with reading LSASS's in-memory credential material, the same technique behind Mimikatz-style credential dumping. Correlation: the SAME `SourceImage` performing more than 5 such accesses within 5 minutes — a single LSASS read can be a legitimate EDR/AV agent or authorized diagnostic tool; a burst from one process is not. DragonForce itself is a well-documented ransomware-as-a-service "cartel" (Barracuda MSP + Trend Micro + Sophos), with a specific citation to the 2025 Co-op and M&S (Marks & Spencer) UK retail breaches.

**2. LAPSUS$, 3. The Gentlemen, and 5. ShinyHunters — identical failed-logon burst signature (T1110, `authentication`).** All three rules share byte-identical detection logic: base match is `EventID 4625` (failed logon) with `LogonType` 2, 3, or 10 (interactive, network, or RDP); correlation fires when the same `SourceIP` produces more than 10 failures within 10 minutes — a classic brute-force/password-spray volume signature (LAPSUS$/The Gentlemen use `gt: 10`; ShinyHunters' correlation is written as `gte: 11`, the identical cutoff expressed the other way). LAPSUS$ is cited via the well-known 2022 Vodafone Portugal disruption (MITRE tracks LAPSUS$ as group G1004); The Gentlemen is a newer ransomware operator (Check Point's own dedicated research writeup, plus a SystemBC C2 server takedown revealing 1,570 victims) tied to a 2026 Romanian energy-sector breach; ShinyHunters (added 2026-09-04) is one of the most consequential extortion actors in this corpus's citation set — tied to the AT&T (73M customers), Snowflake-adjacent, and Instructure breaches, and the subject of a named DOJ federal criminal charge plus an FBI PSA (I-051526-PSA, 2026-05-15). The shared logic here is defensible in a way the T1567/T1486 clusters' sharing isn't as jarring — failed-logon brute-forcing genuinely IS a generic technique multiple unrelated actors use identically, unlike "ransomware appends a distinctive extension," which SHOULD in principle be more actor-specific than these rules make it.

**4. Shai-Hulud (npm worm) and 6. Unknown (tj-actions/reviewdog GHA Supply-chain 2025-03) — printer/scanner administrative-credential harvesting (T1552, `proxy`).** Both rules share byte-identical detection logic, distinct from this corpus's other Shai-Hulud rules (see `nx-shai-hulud-npm-worm-cluster-detection-2026-09-04.md`): base match is a proxy request whose URI stem hits a printer/scanner administrative-credential endpoint (`/addrbook`, `/kmaddrbook`, `/cgi-bin/dynamic`, `/getPassword`, `/network/smb`, `/getSMBCredentials`, `/scanner/credentials`) — these are real, documented multifunction-printer/scanner API paths that expose stored SMB/network credentials when reached without authentication, EXCLUDING requests carrying an ordinary browser user-agent (so a human clicking through a printer's admin web UI doesn't fire this — the exclusion targets automated/scripted access specifically). Correlation: the same `cs-uri-stem` hit 6+ times within 10 minutes. This is a genuinely narrow, distinctive signature — unlike the identical-across-actors clusters, this one actually encodes a specific technique (harvesting credentials cached on networked printer/scanner devices, a real and somewhat under-appreciated credential-access vector) rather than a generic placeholder. The "Unknown" actor (added 2026-09-04) shares its identity with two other techniques already in this corpus (T1078 and T1567 — see this corpus's T1078-logon-anomaly note and the exfil-host-burst note) and is sourced from Unit42, Wiz, CISA, and StepSecurity covering the March 2025 `tj-actions/changed-files` GitHub Action supply-chain compromise (CVE-2025-30066).

## Known limitations (per rule)

**DragonForce (T1003)** cannot distinguish a malicious LSASS dump from legitimate EDR/AV or authorized ProcDump/Windows-Error-Reporting activity generating the same access-mask pattern — its own falsepositives field names this explicitly; an environment running security tooling that legitimately reads LSASS memory repeatedly needs a process-image allowlist before this rule is deployable without excessive noise.

**LAPSUS$/The Gentlemen/ShinyHunters (T1110)** all risk false positives from a user whose cached credentials retry from multiple devices simultaneously after a password change, or from shared egress infrastructure (VPN concentrator, NAT gateway) aggregating many distinct users' failed logons behind one source IP — the original two rules' falsepositives sections name these scenarios explicitly. None of the three rules can distinguish its named actor's specific tradecraft from either of the other two, or from any other brute-force attempt — the actor label on a hit reflects only which corpus entry happened to cite this generic technique first, not evidence the SPECIFIC named actor is responsible.

**Shai-Hulud's and the "Unknown" actor's printer-credential rules** need a proxy log source that actually captures internal traffic to printer/scanner management interfaces, which many environments don't route through a monitored proxy at all (multifunction devices are often reached directly on the LAN). Even where it does apply, the user-agent-based browser exclusion is easily defeated by an attacker who simply sets a browser-shaped user-agent string on their scripted request.

## What to do with a hit

1. **DragonForce (T1003)**: treat as a strong credential-theft-in-progress signal once your own EDR/security-tooling processes are excluded — LSASS access-burst from an unrecognized process is high-confidence malicious.
2. **LAPSUS$/The Gentlemen/ShinyHunters (T1110)**: standard brute-force response — verify against shared-egress/VPN infrastructure before escalating, then rate-limit or block the source; this signature generalizes far beyond any one named actor, so treat a hit as "a brute-force burst occurred," not attribution to a specific group.
3. **Shai-Hulud/"Unknown" (T1552)**: if any networked printer/scanner/MFP in your environment exposes one of the listed admin API paths without authentication, this is a real, fixable exposure independent of whether either specific campaign is present — verify and lock down printer/scanner admin interfaces as a standing hardening item, not just a detection target.
4. Deploy all six against the log sources each requires (process_creation, authentication ×3, proxy ×2).
