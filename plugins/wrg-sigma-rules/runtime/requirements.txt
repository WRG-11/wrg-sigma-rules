# wrg-sigma-rules plugin runtime dependencies.
#
# Every requirement here carries an upper bound at the next major version.
# The reason is not caution for its own sake: an unbounded `>=` constraint is
# already satisfied by every future release, so Dependabot sees nothing to
# propose and stays silent, while a fresh `pip install -r requirements.txt`
# silently picks up a breaking major. That is exactly how mcp 2.0.0 (which
# removed `mcp.server.fastmcp`) broke this plugin's entry-point with every
# recorded CI run still green. Bounds make the upgrade a reviewed PR instead
# of an invisible break.
#
# Core (always required):
# server.py supports both SDK majors (2.x `MCPServer` and 1.x `FastMCP`, which
# are API-compatible for what it uses), so the bound sits at the next unseen
# major rather than excluding 2.x. CI runs the suite against both.
mcp>=1.28.1,<3         # high-level MCP server runtime (server.py entry-point)
pysigma>=1.5.1,<2
# pySigma parses conditions and correlations through pyparsing (a transitive
# dep). pyparsing 3.3.3 changed parse-action handling, and pySigma 1.5.0 breaks
# under it: every rule whose condition combines and/or/not, and some
# correlation rules, fail to convert or convert differently ("'str' object is
# not callable"). pySigma 1.5.1 adapted (SigmaHQ/pySigma#549, #550), hence its
# floor above. That break shipped in a PATCH, so the upper bound admits only
# pyparsing versions this suite has run green on (3.3.2 and 3.3.3); widen it
# once a newer one passes.
pyparsing>=3.3.2,<3.3.4
PyYAML>=6.0.3,<7

# Backend integrations are installed by this requirements file and
# lazy-imported at runtime:
pysigma-backend-splunk>=2.1.0,<3
pysigma-backend-elasticsearch>=2.1.1,<3
pysigma-backend-opensearch>=2.0.3,<3
# Wazuh routes through the elasticsearch Lucene backend above; this repository
# does not bundle a separate Wazuh backend package, and convert_rule emits an
# explicit caveat warning for that route.

# Processing pipelines (lazy-imported; convert_rule config={"pipeline": ...}).
# Without a pipeline a windows/sysmon rule converts to a query that keeps the
# field names but drops the event selection, so these are runtime deps rather
# than optional extras -- the test suite asserts the difference.
pysigma-pipeline-sysmon>=2.0.0,<3
pysigma-pipeline-windows>=2.0.0,<3

# Test deps are not pinned here: install pytest (>=8.0) separately, as CI
# does with `pip install -r requirements.txt pytest`.
